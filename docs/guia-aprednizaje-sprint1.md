# 2. PRESENTACIÓN
 
El trabajo colaborativo constituye una de las competencias más demandadas en los entornos de desarrollo de software modernos.
 
Las organizaciones utilizan plataformas de control de versiones y metodologías ágiles para coordinar equipos, asegurar la calidad del producto y mantener la trazabilidad de los cambios realizados durante el ciclo de desarrollo.
 
En este taller, los aprendices aplicarán prácticas reales de la industria tales como:
 
- Gestión de repositorios Git.
- Trabajo con ramas feature.
- Creación y revisión de Pull Requests.
- Uso de Scrum para administrar el backlog.
- Aplicación de estándares de calidad para la integración de código.
 
Al finalizar el sprint, cada integrante habrá participado activamente en el desarrollo colaborativo de un incremento funcional del producto.

## 3.1 Reflexión Inicial
 
### Actividad
 
Analizar la siguiente situación:
 
> ¿Qué sucede cuando dos desarrolladores modifican simultáneamente el mismo archivo y no existe un mecanismo de control de versiones?
 
### Preguntas orientadoras
 
- ¿Cómo se identifican los cambios realizados por cada integrante?
- ¿Qué riesgos existen al sobrescribir archivos?
- ¿Cómo puede evitarse la pérdida de información?
- ¿Qué ventajas ofrece Git frente al intercambio manual de archivos?
 
### Evidencia
 
Participación en la discusión y registro de conclusiones.

## 3.4 Transferencia del Conocimiento
 
Los aprendices aplicarán los conocimientos adquiridos en el proyecto formativo mediante la ejecución del Sprint.
 
### Actividades
 
#### Desarrollo de historias de usuario
 
Cada integrante deberá:
 
1. Seleccionar una historia del Sprint Backlog.
2. Crear una rama `feature/*`.
3. Implementar la solución.
4. Realizar commits frecuentes.
5. Crear un Pull Request.
6. Atender observaciones de revisión.
7. Integrar los cambios aprobados.
 
#### Trabajo colaborativo
 
- Participar en revisiones de código.
- Resolver conflictos de fusión.
- Mantener actualizado el repositorio local.
- Aplicar la Definition of Done.
 
### Evidencias
 
#### Conocimiento
 
- Explicación del flujo Git utilizado.
 
#### Desempeño
 
- Participación en revisiones.
- Gestión adecuada de ramas.
- Uso correcto de Pull Requests.
 
#### Producto
 
- Incremento funcional del sprint.
- Código integrado en la rama principal.
